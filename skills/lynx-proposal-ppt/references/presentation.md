# 方案结构与可编辑 PPT

每页只表达一个主结论；标题表达结论，正文保留支撑信息。客户方案写业务收益、工作步骤和阶段成果，管理汇报写成果→问题/改进→计划→资源/决策。已有品牌模板优先，默认宽屏、深蓝与青绿色、中文常用字体可配置；没有品牌授权不编造客户 Logo。

来源标识与统计口径放图下注/讲稿，关键限制不能用极小字隐藏。最后一页致谢并给出已确认的下一步。保留客户版与内部支撑表的对应关系。

## 后备工具：PptxGenJS

上游 [gitbrent/PptxGenJS](https://github.com/gitbrent/PptxGenJS)，MIT，固定 npm 4.0.1。脚本是公司编写的简单生成器，提供原生文本、表格、柱状/折线/饼图、讲稿；适合标准方案和汇报，不替代复杂品牌设计。字段数量/文字超过限制时拒绝生成，AI 应拆页，不默默截断。

优先用 WorkBuddy 已有演示能力；仅在需要时由 AI/维护者核对 Node 22+，在 scripts 目录 `npm ci --ignore-scripts`。不安装全局包。

```sh
node scripts/build_deck.mjs templates/deck.json --output 客户方案.pptx
```

在技能根目录执行。输入 JSON 用模板结构，`kind` 支持 bullets/table/chart/closing，每页必须有 title 和 notes（结论依据、来源或示例说明）。输出文件不能已存在；源文件保持不变。默认文本/图表可编辑，布局简洁，页码明确。复杂图片/多图布局请使用已有设计工具或扩展生成器后再检查。

## 交付检查

正式文件在 PowerPoint/WPS 或渲染器逐页查看。检查中文替换字体、折行、单位与颜色含义、无溢出、文本/图表可编辑、备注来源完整。脚本日志只说明已生成文件，不证明客户看过或业务已验收。

完整文件不生成时，保留逐页文案并说明缺少的工具和下一步。任何示例数字均明确是虚构演练，不能进入客户版当事实。
