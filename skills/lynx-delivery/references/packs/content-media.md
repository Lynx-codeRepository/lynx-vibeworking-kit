# 内容工厂与媒介发布

适用：content-media 的内容、媒介、订单、积分、账户、文件、监测和发布节点。必要输入：具体流程、角色、订单/任务及环境，先读当前 HANDOFF、文档入口和 PROJECT_STATUS。

## 方法

1. 沿现有 React/Vite → Java/Spring Boot → MySQL 权威业务链实现。核对当前 Java/Maven 版本；Node 用于前端编译，不擅自引入另一业务后端或数据库。
2. 使用现有服务、显式事务与 Flyway migration。订单明细、积分冻结/扣减/返还、文件和审计保持一致；异常重试要幂等，不重复扣费或发单。
3. 私有 OSS 保存业务文件，数据库保存对象引用与校验信息。上传/下载经过对象权限；前端不接收 AccessKey。保留历史未迁移文件与备份，不能自动清空源库。
4. 控制面、AI 监测 Worker 与发布 Worker 的职责和部署边界分开。复用当前签名、能力声明、短期授权和回调机制，不共享生产库或长期会话密钥给 Worker。
5. AI 稿件保留 brief、事实、生成版本、审查、定向修复与归档链路；发布是独立授权动作。

## 验收与恢复

按任务核对资料 → 需求 → 任务 → 稿件/归档 → 媒介订单 → 发布记录/回链，以及员工、客户、供应商的对象范围。账务改动必须验证并发、失败回滚、重试与余额/流水一致；不用真实扣费作默认测试。

迁移先做清单、计数、哈希与目标备份，明确计划和回滚后按授权实施。未知环境不运行迁移/seed；Worker 用隔离数据或 dry-run，真实渠道与正式扣费另行验证。交付实际变更、证据和运营接力说明。
