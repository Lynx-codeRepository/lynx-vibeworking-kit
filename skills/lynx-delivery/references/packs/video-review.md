# 视频审核与媒体流程

适用：独立视频审核工作台或明确授权的宿主集成。必要输入：作品、版本、原片/审阅副本、目标角色和问题；核对帧率、时长和当前存储，不根据画面猜测帧号。

## 方法

1. 读 PRODUCT、CONTEXT、UX 和 API/宿主接入说明，复用现有播放器、批注与对比组件。独立仓库以 FastAPI/PostgreSQL 为业务后端；接入 DAM 时先明确宿主权威对象，避免复制第二套业务持久化。
2. 宿主负责身份、租户和业务权限。host 模式需要实际实现身份适配，不能只切配置。开发身份、假 token 或开放 OSS 不能作为生产解决方式。
3. 帧与坐标以生成的审阅副本/API 为准。意见绑定正确版本、帧或时间段；版本通过与意见解决是不同状态，不自行强制锁批注。
4. 处理上传、取消、续传、异步转码、失败重试与草稿恢复。新旧版本同步播放、进度与音轨沿用现有约定。

## 验收与恢复

使用合成视频验证：上传 V1 → 精确定位 → 圈画/文字/时间段意见 → 回复 → 上传 V2 → 同步对比 → 状态/分享。按改动验证刷新/断网恢复、密码/过期/撤权、评论与下载权限及移动布局。

项目 check、后端集成和浏览器验证分开记录。私有 OSS 实连、宿主身份、实体手机、原生全屏和生产若未实测就明确未覆盖。媒体处理失败时追踪任务、队列和存储，不删除原片或改变帧索引掩盖问题。
