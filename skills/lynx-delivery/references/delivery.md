# 成果与证据记录

任务说明记录目标与范围；验收记录写用户操作、预期、实测证据和状态；交接说明提供文件、打开方法、限制与后续负责人。现有项目已有正式记录时引用它，不新建重复台账。

安装后的 `.lynx-kit/evidence.json` 使用以下格式。`outputs` 是项目内真实成果文件的相对路径，不能是 Kit 记录文件；引用关键文件即可，不列全部源码。`checks` 填实际执行的验证摘要。

```json
{
  "schemaVersion": 1,
  "task": "客户官网联系表单修复",
  "status": "ready-local",
  "environment": "local",
  "outputs": ["src/contact.ts", "docs/contact-local-verification.md"],
  "checks": [
    {
      "name": "提交成功与失败恢复",
      "status": "passed",
      "evidence": "2026-10-08，本地隔离接口；有效字段提交一次成功，失败后保留输入并可重试；详见验证记录。"
    }
  ],
  "limitations": ["未接入正式邮件服务，未覆盖生产与客户验收。"]
}
```

上面是格式示例，不是已完成的业务证据。未完成时保留 `in-progress`，失败/阻塞验证如实记录；check 返回未通过是正常状态。`ready-local` 只表示本地成果准备交付；此命令不执行项目测试，也不核实证据摘要真伪。

用真实的文件或操作记录支撑结论。未执行、失败、阻塞、跳过、修复后通过分别写清；不能只修改 JSON 状态来让检查通过。线上/生产/客户验收使用现有项目发布记录、真实环境验证和必要签字，不在这个本地结构检查中认证。
