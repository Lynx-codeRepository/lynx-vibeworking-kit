# 页面交付验收

先确定本次用户要完成的动作、页面与角色，再在实际运行入口验证。遵循项目已有设计和业务规则，避免为了评分添加无关流程。

- 主路径能从入口完成到明确结果；成功/失败/加载/空状态可理解，失败不丢输入，不产生重复写入。
- 信息按任务排列，主操作可辨认。字号、对比度、留白和表格便于阅读；不能只给漂亮的截图或静态 HTML 就声称业务完成。
- 桌面与约 390px 窄屏无关键遮挡或横向溢出；触控、键盘焦点、返回和关闭可用。按本次影响补充放大、长内容与适用的设备检查。
- 权限在后端按身份和对象范围执行。隐藏按钮不能替代接口拒绝；Mock、本地身份和演示数据不代表真实集成。
- 复用现有组件和交互。修复观察到的缺陷后复测有关路径，保留可定位的截图/步骤/测试摘要。

最终记录页面、角色、环境、尺寸、日期、实际结果和未覆盖范围。浏览器或目标设备不可用时说明视觉/真机尚未验证，并完成可以验证的部分；不要求用户为了普通检查提供账号或凭据。
