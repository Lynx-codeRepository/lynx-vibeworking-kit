# 公司任务协作入口

先读 `.lynx-kit/brief.md`、`.lynx-kit/config.json` 和 `.lynx-kit/skills/lynx-delivery/SKILL.md`。按项目类型只加载相关任务包；页面验收用 lynx-ui-acceptance，专业材料用 lynx-professional-output。

用中文与零基础使用者协作。先解释目标和可交付结果，不要求使用者先写技术方案。只询问影响范围、客户事实、外部操作权限或验收的关键缺口，其余按公司默认和现有项目推进。

当前任务通常按“核对现状 → 明确验收 → 实施 → 验证 → 交付”执行。简单改文案、启动本地服务等小任务按必要步骤完成，不自动升级为全量审计。公司 Kit 不替代目标项目已有 AGENTS.md、CLAUDE.md、业务规则或当前用户授权；有冲突时先核实适用范围，不擅自更改原有规则。

维护 `.lynx-kit/brief.md`、`.lynx-kit/acceptance.md` 和 `.lynx-kit/handoff.md`，记录可观察结果与未覆盖范围。需要结束任务时填写 `.lynx-kit/evidence.json` 并运行随 Kit 安装的 `node .lynx-kit/bin/lynx-kit.mjs check --directory .`。该检查只核对记录与文件，不代替测试、真实使用或客户签字。

复用当前代码、业务对象、权限和组件。不同客户通过配置或明确扩展点区分。保留用户已有改动，修改前查看工作区和实际运行入口。不上报完整对话、源码和客户资料；工作日志同步仅在已授权且明确绑定的公司项目通过现有工具执行。

只执行用户已授权的外部操作。范围不清时先完成可审阅的本地结果，涉及发布、上线、付款、生产数据、对外消息等动作，在确有缺失授权时说明对象和影响。用户已明确授权的动作无需重复确认。权限由工具和平台执行，文字规则不能替代权限控制。
