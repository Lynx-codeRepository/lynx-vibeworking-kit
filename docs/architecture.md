# 结构与命令

本包分为新人入口、公司任务技能、项目安装器与交付记录。没有 AI 模型调用、远程服务或第三方运行时依赖；不包含公司业务系统源码或客户数据。

```text
START-HERE.md             新人自然语言入口
catalog.json              八类任务与输出要求
skills/                   三个技能及相关专业任务包
templates/                任务、验收、接力、证据与协作入口
bin/lynx-kit.mjs           CLI 入口
lib/kit.mjs               文件计划、安装、检查与验证
tests/                    安装与证据安全回归
.github/                  CI、Issue 与 PR 模板
docs/                     工具、示例、来源、维护与验证
```

## 命令约定

| 命令 | 输入与行为 | 退出码 |
| --- | --- | --- |
| catalog | 输出任务类型；`--json` 可供 AI 解析 | 0 |
| init | `--directory --type --name --goal`；目标不存在或为空；`--tool` 默认为 all | 0 成功；1 输入/冲突错误 |
| attach | 同上；目标必须已存在；保留已有 AGENTS/CLAUDE | 0 成功；1 输入/冲突错误 |
| doctor | `--type` 可选；仅通过版本命令判断工具可调用 | 0 全部可调用；2 有未就绪项 |
| check | `--directory` 必需；读取项目证据、检查成果文件 | 0 记录通过；2 未准备好；1 读取/输入错误 |
| validate | 检查本包任务目录、技能结构、文档本地链接 | 0 通过；2 存在问题 |

安装命令支持 `--dry-run`，列出计划且不写文件；所有结果可使用 `--json`。工具名可选 codex/claude/cursor/all。命令不会执行目标项目脚本、安装依赖、启动服务、改全局设置、读取凭据或访问网络。

## 安装后的目录

核心快照存放于目标项目 `.lynx-kit`，包括本地可执行的 CLI、专业技能、指引、任务记录与版本配置。Codex 使用 `.agents/skills`，Claude 使用 `.claude/skills`，Cursor 使用 `.cursor/rules/lynx-kit.mdc`。按所选工具创建项目入口；存在旧 AGENTS/CLAUDE 时保留原文件。

所有路径先检查冲突与符号链接，再逐个独占写入。中途常规写入错误会撤销本次已新建文件与目录，不删除已有内容。进程强制终止或并发修改不能保证事务回滚，需人工核对新增文件，不能自动 reset/clean。

目标与 Kit 源码目录必须分离，避免误将源码当成被安装项目。目录参数需有真实、已存在的父目录；`init` 不是业务应用生成器，生成的是带专业指引的任务工作区。

## 验收检查的实际范围

项目 `check` 要求 `ready-local`、local 环境、至少一个存在且非空的成果文件、至少一项 passed 验证摘要和 limitations 数组。拒绝越界/符号链接成果路径和将 Kit 记录冒充成果。它无法判断测试摘要真假、业务是否正确或客户是否签字。

维护者 `npm run check` 则验证 Kit 自身并运行回归测试。两种检查的对象不同；真实任务仍需按对应任务包执行测试或渲染验证。
