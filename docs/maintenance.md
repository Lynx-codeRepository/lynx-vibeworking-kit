# 维护与试用

每次更新核对上游许可、是否归档、功能入口、依赖和外部账号要求，更新 resources.json 的日期与固定提交。目录中的链接不触发自动下载执行。员工只拿技能 ZIP；完整包留给维护者。

修改流程或工具后运行 `npm run check`；PPT 工具测试需要先在该技能脚本目录 `npm ci --ignore-scripts`，Excel 测试需要安装固定 requirements。运行 `python3 scripts/build_packages.py --output /新发布目录` 生成五个独立 ZIP、完整包及 SHA256SUMS.txt；不把依赖和客户材料打进去。

语义版本：流程/文案修正用补丁版，新增任务能力用次版本。v0.2.0 是办公任务重构，与 v0.1.0 的任务类型不兼容；旧任务保留其原 `.lynx-kit`，新建任务使用新版。不在旧工作目录自动覆盖。更新 WorkBuddy 技能前保留任务输出；在技能 UI 按当前平台流程替换/重新导入，并核对版本。

建议首轮试用覆盖：一份客户方案 PPT、一份客户调研、一份真实脱敏运营表。记录 WorkBuddy 版本、已启用工具、导入结果、来源是否可追溯、文件是否可编辑、员工耗时和具体卡点。真实员工试用未经记录，不能宣称已经通过。
