# 维护与更新

公司项目负责人维护真实业务基线；Kit 维护者更新任务包和工具入口；使用者反馈卡点与结果。不要把一次任务失败扩大为所有项目的硬性约束。

新增或修改任务包时：核对适用项目与来源，补充具体方法与验收，更新 catalog 和文档导航，运行 `npm run check`。涉及安装和路径处理时补有意义的回归测试。新工具先核对官方文档与实际环境，不以新建文件代替端到端使用验证。

## 升级已安装项目

v0.1.0 不提供自动覆盖升级。先读 `.lynx-kit/config.json` 了解版本，保留 brief、acceptance、handoff 和 evidence。让 AI 对照新版本列出文件差异，在明确范围后更新技能和工具入口，禁止覆盖原有项目规则或未经确认丢弃任务记录。

## 移除 Kit

先保存任务与验证记录，再核对由本次安装新增的 `.lynx-kit`、同名技能、Cursor 规则和可选 AGENTS/CLAUDE。只有确认文件仍属于 Kit 且没有其他内容时才能移除；原有规则与项目文件保留。不要执行整个项目的 reset、clean 或递归删除未知目录。

## 公司治理

关键改动由一名非作者审查，负责人管理合并、发布和真实业务验收。初始仓库建立可直接初始化 main，后续变更按 Issue/PR 模板工作。CI 只检查 Kit 自身，不负责业务系统部署。

组织当前套餐为 Free；私有仓库分支保护、Rulesets 和强制审查能否启用要以当前 GitHub 功能与权限核对。本包不声称审查要求已被平台强制执行。不要为了配置门禁自动升级收费套餐。
