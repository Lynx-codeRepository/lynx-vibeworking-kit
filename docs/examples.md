# 公司任务示例

把相关资料交给 AI，再用类似的自然语言启动。下面都是任务示例，不代表已完成这些业务，也不构成线上操作授权。

| 场景 | 可以复制的目标 | AI 应交付 |
| --- | --- | --- |
| 官网 | 请沿用现有官网风格，把产品介绍和联系表单做完整，并验证手机上的提交失败恢复。 | 真实本地预览、表单闭环与验证记录 |
| 资产审核 | 请定位指定资产提审一直排队的原因，修到审核、修订版、入库和下载一致。 | 根因修复、版本/角色闭环和实际文件校验 |
| 视频审核 | 请在现有工作台实现两版同步对比，保留每版独立意见，验证切换和音轨。 | 可用功能、帧/版本证据与集成边界 |
| GEO | 请用这些产品资料写一篇面向家庭用户的品牌文章，建立来源账本；先交付稿件。 | 可靠正文、来源与未知事实清单 |
| 内容媒介 | 请修复归档投放失败后的积分状态，验证事务回滚和重复操作不会再次扣费。 | 隔离测试、账务一致性与修复说明 |
| 小程序 | 请复用现有页面和请求封装，增加业务需求表单，验证授权拒绝和网络失败恢复。 | 目标平台预览与真机待测/已测记录 |
| 内部工作台 | 请为管理员做项目进度汇总，成员只能看授权范围；先用隔离数据验证。 | 可用看板、权限与数据口径 |
| 专业材料 | 请用这些资料完成给老板看的季度汇报文字，我确认后再制作 PPT，备注要自然。 | 可审阅文字，授权后实际 PPT 与渲染检查 |

## AI 的安装示例

取得 Kit 后，使用 Node.js 22+；不要把包放在要接入的项目内部。以下路径是示例，需要换成实际已核对的目录。

```bash
node bin/lynx-kit.mjs attach --directory ../current-project --type geo-content --name "品牌稿件" --goal "完成有来源的品牌文章" --tool codex --dry-run
node bin/lynx-kit.mjs attach --directory ../current-project --type geo-content --name "品牌稿件" --goal "完成有来源的品牌文章" --tool codex
```

在目标项目读取 `.lynx-kit/START.md`。完成后，AI 根据真实验证填写记录，再执行：

```bash
node .lynx-kit/bin/lynx-kit.mjs check --directory .
```

如果用户只是要一份文章或简单分析，可直接读取有关技能完成，不必为了使用 Kit 新建仓库或安装所有工具。
